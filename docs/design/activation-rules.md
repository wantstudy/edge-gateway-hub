# iot-daq 激活规则与生命周期决议（对应计划 task 42）

> 配套图：`docs/design/activation-state-machine.svg`（双状态机 + 迁移表）、`docs/design/activation-reissue.svg`（换机时序图）。
> 硬约束（访谈决议）：**激活必须联网（无离线激活）**；离线宽限 7 天；心跳周期 24h；试用 3 天到期降级而非停用；**废弃 / 重发入口仅在总管理后台（经云端），客户端无任何废弃 / 解绑 / 重置试用入口**。

## 1. 激活请求 / 响应契约（字段级）

> 完整 API（含错误码 / 幂等语义 / admin 端点）以 task 44 `licensing-api.md` 为准；此处固化激活与心跳的最小字段集，供 task 45/46 实现与 task 40 架构图引用。

### 1.1 `POST /activation`（激活 + 绑定）

请求字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `activation_code` | string | 用户输入的激活码（厂商发放） |
| `machine_code` | string | 机器码组合指纹（HMAC-SHA256 加盐截断，task 41） |
| `anchor_hashes` | string[5] | 逐锚点同盐 HMAC 哈希集（供 N-of-M 同机判定） |
| `device_pubkey` | string | 设备侧生成的公钥（绑定设备身份，后续心跳 / 回执验签） |
| `nonce` | string | 客户端随机数（响应需回显，防跨请求错配） |
| `ts` | int64 | 请求时间戳（UTC 秒） |
| `req_sig` | string | 设备私钥对以上规范字段的签名（证明持有私钥） |

响应字段（`200`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `lease_id` | string | 租约 ID（device 1:N lease，task 41） |
| `lease_token` | string | 厂商 Ed25519 签名的租约令牌（含 kid） |
| `tier` | string | 授权档位（正式 / 免费版能力上限） |
| `verify_mode` | enum | 二次校验档位 A / B / C（随 Token 下发，task 44） |
| `valid_until` | int64 | 租约到期时间（UTC 秒） |
| `heartbeat_hours` | int | 心跳周期（固定 24） |
| `server_time` | int64 | 服务端时间（客户端时钟校准与回拨检测用） |
| `nonce` | string | 回显请求 nonce |
| `sig` | string | 厂商私钥对响应规范字段的签名（本地用内置公钥集验签） |

关键错误码：`403 CODE_REVOKED`（码已废弃）、`403 CODE_BOUND_TO_OTHER_DEVICE`（同码异机，task 41 冲突检测）、`400 INVALID_CODE`、`409 NONCE_REPLAY`、`401 TIMESTAMP_SKEW`（超出 ±5min 窗）。

### 1.2 `POST /heartbeat`（每 24h）

请求：`{ lease_id, device_sig(设备私钥), ts, nonce, receipt_cursor(B 档：最近审计回执序号区间) }`；
响应 `200`：`{ server_time, next_deadline, valid_until, tier, sig }`；
响应 `403 LEASE_REVOKED`：原码被后台废弃 → 客户端立即进入降级 / 停止北向转发（废弃语义见 §4）。

## 2. 宽限期与心跳规则

- **心跳周期 24h**：成功即刷新 `last_heartbeat`；B 档随心跳附审计回执（序号区间 + 条数 + 摘要，无业务数值；断网允许延迟补报）。
- **宽限期 7 天**：心跳失败 / 断网起计（守卫：`last_heartbeat + 7d > now` 且时钟校验通过）。宽限内**北向转发继续**、全局横幅提示；恢复心跳即回 Active。
- **超期（> 7 天）→ 降级 / 受限**：**停北向转发、保留本地采集与断点缓存**、横幅告警；恢复心跳可自动回 Active。
- **租约有效期耗尽或被后台废弃** → 停止北向转发（不可自动恢复），本地采集保留，唯一出路是重新激活（后台重发新码）。
- **时钟守卫**：单调时钟 + 记录历史最大时间 + 与服务端时间比对；**回拨不延长宽限期与试用期**，判异常并记审计。

## 3. 试用 3 天 → 降级免费版衔接

- 首次启动进入试用（3 天倒计时，以云端首次激活时间为兜底，重装不重置）。
- **试用到期 → 降级免费版（降级而非停用）**：仅 Modbus 协议、最多 8 设备、采样间隔 ≥1s、**无北向转发、无 OTA**；本地采集持续，数据留在本地可导出。
- 输入正式激活码联网激活成功后恢复 Active 与完整功能。

## 4. 废弃语义决议：**立即失效**（非到期失效）

- **决议**：后台确认废弃 → 服务端**即时**置 `Revoked` 并作废原设备租约 → 原设备**最迟下一次心跳（≤24h）被拒** → 进入降级 / 停止北向转发（本地采集保留）。
- **理由**：换机与风控场景都要求把越权使用窗口压到最短——立即失效的风险窗口 ≤24h（一个心跳周期）；若采用「到期失效」，原设备将合法使用至租约期末，留下**最长一个完整有效期**的越权窗口，与「废弃即切断」的业务预期不符。
- 全链审计留痕（操作者 / 时间 / 原因 / 幂等键）；废弃与重发支持后台合并执行（换机工单 ≤3 次点击）。

## 5. 换机重发约束

- 新码**可继承**原 tier 与有效期（后台可覆盖）；`reissued_from` 建立溯源链，激活码详情页时间线可见（发放 → 绑定 → 废弃 → 重发）。
- **一码多机默认禁止**：激活码与设备 1:1 绑定（task 41 冲突检测：同码异机 → 403 `CODE_BOUND_TO_OTHER_DEVICE`）。
- 重发支持两种模式：**预绑定新机器码** 或 **留待首次激活时绑定**；废弃与重发**同事务**且接口**幂等**（重复提交不产生第二个新码）。
- 换机时序（五步不缺，详见 activation-reissue.svg）：客户换机 → 后台查到原激活码 → 废弃（原设备立即失效）→ 重发新码 → 新机联网激活 + 审计留痕。

## 6. 失败路径清单（≥4，对应状态机红色路径）

1. **激活码已废**（`Revoked`）→ 激活被拒，停留未激活 / 试用态，提示申请换机。
2. **机器码不匹配**（同码异机）→ 403 拒绝，引导后台「废弃 + 重发」。
3. **服务器不可达** → 进入宽限（≤7 天，北向继续）；超期 → 降级：停北向转发、保留本地采集。
4. **时钟异常（回拨）** → 判异常：不延长宽限与试用；单调钟 + 服务端时间比对；记审计。
