# iot-daq 总管理后台线框：激活码生命周期管理域（对应计划 task 44）

> 定位：与 `ui-admin-console.md`（task 64 全后台 10 页界面设计）**互补不重复**——本文件聚焦**激活码生命周期管理域**（发码 / 废弃 / 重发 / 审计 / 密钥）的页面结构与交互约束，作为 API 契约（`licensing-api.md`）的消费侧依据；视觉与全局规范以 `ui-design-system.md` 为准。
> 全局约束：**废弃 / 重发仅厂商管理员可见可用**（客户端无任何解绑入口）；危险操作四要素齐全；换机工单 ≤3 次点击；写操作全部幂等 + 全量审计。

## P1 激活码列表页

- **目标**：快速定位任意激活码，按生命周期状态管理。
- **关键元素**：状态筛选 chips（已发放 / 已绑定 / 已废弃 / 已重发，对齐状态机 4 态）+ 租户 / 订单 / tier / 时间范围筛选；列表列：码值（掩码）· 状态 badge · 绑定设备（掩码）· tier · 有效期 · 来源订单 · 创建时间；「导出」「批量发放」入口。
- **关键交互**：点击行进详情；筛选即改 URL query（可分享）；导出走后端（含审计）。
- **依赖 API**：`GET /admin/codes`。
- **验收要点**：5 种状态 badge 与 data-model 枚举一一对应；码值默认掩码。

## P2 激活码详情页（生命周期中枢）

- **目标**：查看单个激活码全生命周期与绑定设备实况，发起高危操作。
- **关键元素**：① **生命周期时间线**：发放 → 绑定 → 废弃 → 重发（每步含操作者 / 时间 / 原因）；② **溯源链**：`reissued_from` 前后码以链式卡片可视化（可跨级跳转）；③ 绑定设备卡片：machine_code 掩码 · 部署形态（native / docker + 镜像 digest）· 最近心跳 · 租约状态；④ 回执连续性 24h 区间覆盖图（跳空 / 缺失标记）。
- **关键交互**：**「一键换机」工单 = 废弃 + 重发合并执行（≤3 次点击）**：点「换机」→ 废弃弹窗（P3）→ 重发对话框（P4）自动带入原码上下文；单独「废弃」「重发」按钮仅对授权运营角色可见。
- **依赖 API**：`GET /admin/codes/{id}`；`POST /admin/codes/{id}/revoke`；`POST /admin/codes/{id}/reissue`。
- **验收要点**：时间线四步不缺；非管理员角色看不到高危按钮（RBAC 门控演示点）。

## P3 废弃确认二次弹窗（DangerConfirmModal · 全系统最危险操作）

- **目标**：强制操作者理解后果并留下可审计的原因。
- **关键元素（四要素，缺一不可提交）**：
  1. **影响清单**：明示「**原设备将立即停止北向转发（本地采集继续）**」「原激活码不可恢复」「最迟下一次心跳（≤24h）被拒」；
  2. **原因必填**（枚举：换机 / 风控异常 / 客户要求 / 其他）；
  3. **补充说明 ≥10 字**；
  4. **输入该激活码后 8 位**二次校验；
  - 可选：双人复核开启时显示「待第二管理员审批」状态条。
- **关键交互**：输入后 8 位不符 → 禁用提交按钮并提示；提交 → `POST /admin/codes/{id}/revoke`（幂等）；成功后 toast 提示「已立即失效，设备将在 ≤24h 内降级」并写审计。
- **依赖 API**：`POST /admin/codes/{id}/revoke`。
- **验收要点**：四要素齐备；不填原因 / 尾号不符时提交被拦截；影响文案含「立即失效」。

## P4 重发对话框

- **目标**：废弃后安全地签发新码，保持溯源与商业条款。
- **关键元素**：绑定模式**二选一**（单选）：「预绑定新机器码」（输入 machine_code，后端校验未绑定他码）｜「留待首次激活时绑定」；「继承 tier」「继承有效期」开关（可覆盖，覆盖值表单）；溯源提示条：`reissued_from = <原码>`；幂等说明文案。
- **关键交互**：与废弃**同事务**提交（换机工单路径）或独立发起（须原码已废弃，否则 `409 ORIGINAL_NOT_REVOKED` 提示）；提交 → 展示新码 + 一键复制；重复提交同 `idempotency_key` 返回同一新码（界面提示「已存在重发结果」）。
- **依赖 API**：`POST /admin/codes/{id}/reissue`。
- **验收要点**：两模式互斥且必选；溯源关系在详情页时间线可见；同 key 重放不产生第二个新码。

## P5 设备列表页（含容器形态）

- **目标**：按租户 / 形态巡检设备授权实况，定位回执异常。
- **关键元素**：筛选：租户 / 部署形态（native / docker）/ 租约状态 / machine_code；列：设备 · 租户 · machine_code（掩码）· 部署形态 + 镜像 digest（docker）· 最近心跳 · 租约状态 · 回执连续性摘要（近 24h 覆盖率 / 跳空数）。
- **关键交互**：行进设备详情（心跳时序图 + 回执区间覆盖图，跳空 / 缺失区分标记）；异常设备仅可「**标记异常（备注）→ 转人工核实**」——**无「判定破解 / 封禁」动作**；容器设备行悬停提示「容器重建不产生新设备记录」。
- **依赖 API**：`GET /admin/devices`。
- **验收要点**：deploy_mode / image_digest 列存在；无自动封禁入口（与 task 64 Must NOT 一致）。

## P6 租户列表页（档位配置）

- **目标**：管理租户及其默认二次校验档位。
- **关键元素**：列：租户 · 默认档位（A / B / C，**B 默认高亮**）· 设备数 · 激活码数 · 最近激活时间；档位编辑弹窗（改档需系统角色 + 理由，写审计；提示「档位随 Lease Token 下发，设备级可覆盖」）。
- **依赖 API**：`GET /admin/devices?tenant_id=` 聚合；档位配置端点（系统域，归 task 57 权限矩阵）。
- **验收要点**：B 档默认标识；改档留痕。

## P7 审计日志页

- **目标**：全量操作可追溯，支撑风控与合规。
- **关键元素**：筛选：操作者类型（admin / system / device）/ 动作（issue / revoke / reissue / activation / heartbeat…）/ 实体 / 时间范围；列表：时间 · 操作者 · 动作 · 实体 · IP；行展开 `detail` JSON（原因 / 幂等键 / 冲突检测命中项）；页顶常驻说明卡：「**回执异常 ≠ 破解**——跳空 / 缺失可能由断网补报等合法原因导致，一律人工核实」。
- **依赖 API**：`GET /admin/audit/logs`。
- **验收要点**：revoke / reissue 记录含原因与第二审批人（如启用）；页只读可导出。

## P8 RBAC 角色视图（权限矩阵）

- **目标**：显式呈现角色-权限映射，为 task 57 鉴权实现提供输入。
- **关键元素**：矩阵：行 = 四角色（运营 / 授权运营 / 风控 / 系统），列 = 页面 / 操作（列表·详情·发放·**废弃**·**重发**·档位配置·密钥轮换·审计导出）；高危列（废弃 / 重发）标注「仅授权运营及以上 + 可选双人复核」；「双人复核开关」「会话超时」配置入口（系统角色）。
- **验收要点**：客户端角色不存在于此矩阵（客户端无任何后台入口）；废弃 / 重发列与 API `403 ADMIN_ONLY` 语义一致。

## 交互红线汇总（本域）

1. 废弃 / 重发：仅厂商管理员；客户端与数据模型均无解绑接口。
2. 废弃弹窗四要素（影响清单 / 原因必填 / 补充说明 / 尾号校验）缺一不可提交。
3. 废弃 = 立即失效：影响文案必须出现「立即 / ≤24h」。
4. 回执异常仅人工核实，无自动封禁。
5. 换机工单（废弃 + 重发同事务幂等）≤3 次点击完成。
