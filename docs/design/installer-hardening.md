# iot-daq 安装程序防破解设计（对应计划 task 43）

> 配套图：`docs/design/installer-hardening.svg`（六环节安全链路 + 三个专项框 + Tier 定案）。
> 定位声明：**提高成本 ≠ 绝对防破解**。量化目标：拦掉 90% 非专业破解尝试；专业破解者付出 > 数人日仍无法获得云端有效授权。预算分配：控制面（云端 + 后台）: 客户端 = 7 : 3。

## 1. 安装包签名

- **Windows**：OV / EV 代码签名证书对 NSIS / MSI 安装包做 Authenticode 签名，附 **RFC 3161 时间戳**（证书过期后旧包仍可验）；安装器 / OS 层校验签名链。
- **Linux**：deb / rpm 走**包签名 + 仓库 GPG 校验**；AppImage 附签名文件并在启动器 / 文档中提供验签命令；仅从官方渠道 / 官方仓库分发。
- **校验失败行为**：签名校验失败或无签名 → **拒绝安装**（安装器与文档双重提示）。

## 2. 内容完整性（payload manifest）

- 安装包内嵌 **payload 哈希清单 manifest**（SHA-256 逐文件），安装器逐文件校验。
- **实现边界（与 task 50 对齐）**：安装器负责「安装时校验」；运行期的完整性由程序自检负责（§3），安装器不做二次加密或重打包。
- **校验失败行为**：任一哈希不符 → **中止安装并清理半成品**，提示重新获取分发物。
- 官网公布安装包整体哈希；离线现场提供 tar 哈希清单 + 校验脚本（容器侧见 §10）。

## 3. 运行时自检

- **二进制完整性**：段哈希 / 签名自检（启动时 + 关键授权节点 + 低频周期），算法 SHA-256 段清单，随构建产出（task 49 落地）。
- **关键资源**：前端资源、配置模板等按完整性清单哈希比对——**前端资源校验由 Rust 在启动时执行**（前端自身不可信，见 §5）。
- **校验失败行为**：检测到篡改 → **受限模式 = 停北向转发 + 审计告警**（本地采集不停，对齐 task 40 / 42 状态机）；不静默、不闪退，保证现场可观测。

## 4. 反调试 / 反篡改定位声明与 Tier 定案

- **定位声明**：反调试 / 反篡改**只做提高成本、不做绝对防破解**；拒绝内核驱动与 rootkit 级手段。
- **Tier-1 必做**：代码签名（全平台）+ 构建硬化 **strip / LTO / panic=abort** + 字符串与常量混淆 + 段哈希自检 + **低成本反调试**（用户态检测调试器 / 注入迹象）。
- **Tier-2 暂不做**：控制流平坦化、字符串加密、模块交叉校验、Frida 检测（收益 / 成本比低，维护负担重，待 Tier-1 数据评估后再议）。
- **Tier-3 明确不做**：内核驱动、VMProtect / Themida 级商业壳、硬件加密狗（与 Must NOT Have 一致；理由：Tauri / 杀软冲突、误报率高、维护成本不可接受）。
- **预算**：控制面 : 客户端 = **7 : 3**；**量化目标**：拦掉 90% 非专业破解尝试，专业破解者付出 > 数人日仍拿不到云端有效授权。

## 5. 授权判定位置原则（前端不可保密）

- 授权判定与防篡改判定**必须在 Rust 侧**；WebView / JS 层**只做展示与可见性**，不得作为授权判定依据（前后端边界：数据面行为由 Rust 状态机驱动，JS 仅渲染状态）。
- **前端资源等同公开源码**：Tauri 打包的 JS / CSS 可解包读改——因此：① 判定绝不放 JS；② 前端资源只做**完整性清单哈希校验**（Rust 启动时校验，失败进受限模式）；③ 机密（密钥、激活码、签名算法细节）一律不放前端。

## 6. 防逆向 ≠ 防拷机（两个威胁分治）

- **防逆向**：提高逆向与篡改成本 → 本文件 §3/§4（Tier-1 二进制加固）。
- **防「拷给第二台机器用」**：→ **机器码绑定 + 一机一码**（task 41 指纹 / N-of-M / 冲突检测）+ 云端租约绑定。
- 两条线**不得混入彼此范畴**：二进制加固不承诺防拷机，机器码绑定不依赖代码保密。

## 7. 防御不住什么（自曝，避免客户预期错位）

1. **专业破解者可 patch 二进制绕过本地判定**：Tier-2/3 不做的前提下，只能提高成本与可检测性（自检 → 受限模式 + 云端心跳缺序号区间告警），不能绝对阻止；B 档下破解代码还可**抑制审计回执并完全断网静默自用**（只能发现、无法阻止，见 threat-model.md）。
2. **前端资源不可能保密**：等同公开源码，可解包读改——防御目标是「判定不依赖前端」而非「前端保密」。
3. **全盘格式化 + 换整机**与「全新安装」不可区分（新试用期合法获得，与换机路径一致，商业上可接受）。
4. **断网 + 长期时钟回拨**只能靠本地 max_seen 兜底，无法完全检测。

## 8. 试用标记多重冗余（四重交叉校验）

- 四处：① 标记文件（`license/trial/`，DPAPI / keyring 加密）② 注册表 / 独立配置目录 ③ SQLCipher 库内加密记录 ④ **云端首次激活时间**。
- **交叉校验**：任一不一致 → 取**最早时间**，判异常并记审计；禁止明文 / 可逆弱混淆存储（Must NOT Have）。
- **单点被删兜底推演**：删 ①/②/③ 任一 → 其余三处仍在，试用不重置；本地全失（全盘格式化）→ 以云端首激时间恢复试用与绑定；同宿主重建容器 → 不重置（§10）。

## 9. 时钟回拨检测

- 三层：**单调时钟**（Win `QueryPerformanceCounter` / Linux `CLOCK_MONOTONIC`）+ **历史最大时间 `max_seen`**（冗余存放于 §8 四处，交叉恢复）+ **与服务端时间比对**（激活 / 心跳响应 `server_time`）。
- 判定：`now < max_seen − 容差` → 回拨异常：**不延长试用期 / 宽限期**（到期按 max_seen 计算）、判异常记审计；与服务端时间恢复同步后自动解除。状态机的时间守卫（task 42 迁移表第 7/8 行）引用本节。
- 残余：断网 + 长期回拨无法完全检测（§7.4）。

## 10. Linux 容器化交付场景（镜像 = 分发物）

- 镜像纳入同一防篡改体系：**cosign 签名 + `cosign verify`**、**digest 固定**（compose 以 digest 引用）、**离线 tar 包哈希清单 + 校验脚本**（`docker load` 之前执行；细节归 task 59）。
- **红线**：**镜像可写层不得承载试用标记 / 租约 / 授权状态**——必须落宿主持久卷 `/var/lib/iot-daq`（`license/`、`trial/`），使 `docker rm && docker run` 无法重置试用。
- 推演：同卷重建 → 试用与租约保持；空卷重建 → 视为新装但**宿主指纹相同** → 云端识别为同一设备 + 云端首激时间 → 「换容器重置试用」不成立。镜像内不含敏感物（无私钥 / 激活码 / 宿主指纹 / 默认口令）。

## 11. 口径对齐

- task 40：受限模式 = 停北向转发 + 审计告警；残余风险自曝（threat-model.md）。
- task 41：防拷机由机器码绑定 + 一机一码承担。
- task 50：payload manifest 的实现边界。
- task 59：cosign / digest / 持久卷 / 宿主锚点。
- Must NOT Have：无内核驱动 / 硬件加密狗 / 明文或可逆弱混淆存储。
