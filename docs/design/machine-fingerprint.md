# iot-daq 机器码指纹与一机一码绑定设计（对应计划 task 41）

> 配套图：`docs/design/machine-binding.svg`。
> 核心口径：**一个激活码 ↔ 一台设备机器码（activation_code 1:1 device，device 1:N lease）**；指纹本地计算、原始锚点不出设备；容器形态锚点只取宿主机（与 task 59 完全一致）。

## 1. 锚点清单（M=5）

| # | 锚点 | 取用方式 | 是否易变 | 稳定性权重 | 平台差异（Win vs Linux） |
|---|------|---------|---------|-----------|------------------------|
| 1 | 主板 / BIOS UUID | SMBIOS / DMI 读取 | 稳定（换主板才变） | 高（4/4） | Win：WMI（Win32_ComputerSystemProduct）；Linux：`/sys/class/dmi/id/board_serial`、`product_uuid` |
| 2 | 系统盘序列号 | 存储层枚举系统盘 | 较稳定（换系统盘 / 部分虚拟化迁移会变） | 中高（3/4） | Win：Storage/MSFT_Disk API；Linux：`/sys/block/<dev>/device/serial`（或 udev 属性） |
| 3 | 首个物理网卡 MAC | 枚举物理网卡，排除虚拟 / USB，固定排序取首个 | 易变（换网卡、网卡顺序变化） | 中（2/4） | Win：`GetAdaptersAddresses` 过滤虚拟；Linux：`/sys/class/net/` 排除 `lo`/`veth*`/`docker0` |
| 4 | 系统 machine-id / MachineGuid | OS 安装期生成的机器标识 | 易变（**OS 重装即变**；是安装 ID 而非硬件 ID） | 中低（1/4，仅作辅助） | Win：注册表 `MachineGuid`；Linux：`/etc/machine-id` |
| 5 | CPU 特征（型号 / 家族 / 步进 / 核数） | CPUID / 平台 API | 稳定但弱唯一（同型号大量重复） | 中（2/4，弱唯一辅助信号） | 两平台均可取；仅参与组合，不单独判定 |

> 权重（高/中/低）仅用于**诊断排序与人工核实参考**（如展示「哪一项漂移了」），**不改变判定阈值**——判定按命中计数执行（见 §3），避免单点权重被攻击者针对性利用。

## 2. 指纹算法

```
原始锚点(5 项) → 归一化（trim、大小写统一、分隔符统一）
             → 固定排序拼接（sorted concat）
             → HMAC-SHA256(盐 = 厂商私密常量，编译期注入 / KMS 保管)
             → 截断 128 bit（32 hex）→ machine_code（对外唯一设备标识）
```

- **分支输出**：逐锚点以同盐单独 HMAC → `anchor_hashes[5]`，随激活请求上报，用于 N-of-M 比对；服务端**只存锚点哈希，不见原文**。
- **为何不用裸哈希**：硬件标识取值空间有限（厂商/型号枚举有限、MAC 段可枚举），裸 SHA-256 可被离线字典**预计算/逆推**；盐化 HMAC 使预计算不可行，截断控制泄露面，组合指纹无法还原锚点原文。
- **原始锚点不出设备**：对外仅暴露 `machine_code` 与 `anchor_hashes`，前端 / JS 层不参与任何指纹计算与判定（对齐 task 40）。

## 3. N-of-M 容错规则（阈值 N=4，M=5，允许 1 项漂移）

**判定规则**：当前锚点哈希集与绑定记录比对，**命中 ≥4/5 → 同机**；**命中 ≤3/5 → 异机**。

**理由**：
- 单锚点漂移（换网卡、加硬盘、虚拟化迁移、OS 重装）均为合法运维，必须容忍 → 允许 1 项漂移；
- 2 项及以上同时变化在合法运维中罕见（且可叠加「重装 + 换盘」组合），大概率是异机/伪装 → 不容忍，避免「漏判优先于误杀」失衡；
- 计数制实现简单、可解释、可审计（审计日志记录命中项与漂移项），不引入权重博弈空间。

**推演示例**：
1. **换网卡（合法运维）**：MAC 1 项漂移 → 命中 4/5 → 仍判同机 ✓，租约继续，无需重发激活码。
2. **整机更换**：BIOS / 磁盘 / MAC / CPU 多项变化 → 命中 ≤3/5 → 判异机 ✗，激活被拒 → 走管理后台「废弃 + 重发」（task 42）。
3. **同宿主重建 / 升级容器**：锚点全部来自宿主机且不变 → 命中 5/5 → 同机 ✓，不需重新发码（口径 = task 59）。

## 4. 本地存储与保护

- **Windows**：`%ProgramData%\iot-daq\license\` + DPAPI（CurrentUser）加密。
- **Linux**：`/var/lib/iot-daq/license/` + keyring（或等效系统凭据库）加密。
- **多位置冗余**：主副本 + 备份副本（注册表 / 独立配置目录），交叉校验；单点被删 → 其余副本 + 云端首次激活时间兜底，试用 / 绑定不被重置。
- **Docker 形态**：一律落**宿主持久卷** `/var/lib/iot-daq`（`license/`、`trial/`）；镜像可写层承载授权数据清单为「空」，`docker rm` 重建不重置（对齐 task 43/59）。
- **权限**：仅服务账户可写，普通用户只读；凭证不明文落盘（对齐 Must NOT Have）。

## 5. 重装 / 恢复路径

- **仅 OS 重装**：`machine-id`/`MachineGuid` 漂移 1 项 → 命中 4/5 → **判同机**；重算指纹与绑定记录不一致时，由服务端按 N-of-M 规则**自动更新绑定、重签租约**（审计留痕），用户无感。
- **指纹不可复现**（系统盘一并更换 / 整机迁移 P2V 等，命中 ≤3/5）：判异机、激活被拒 → 管理后台「废弃 + 重发」换机流程（task 42）；**客户端无任何自行解绑 / 重置入口**。

## 6. 容器化锚点来源（Linux Docker，口径与 task 59 一致）

- **锚点只来自宿主机**：只读挂载 `/etc/machine-id`、`/sys/class/dmi/id/product_uuid`（`--mount type=bind,readonly`）；宿主首个物理网卡 MAC 由**安装脚本采集**并写入 `host-fingerprint.json`（HMAC 签名）只读挂载进容器。
- **容器内锚点禁用（红线）**：容器 `/etc/machine-id` 由 runtime 生成、veth MAC 随机、容器主机名 = 容器 ID——`docker rm` 重建后三者全变，会导致授权立即失效、且 SQLCipher 本地库（HKDF 机器码派生密钥，task 34）解不开。
- **容器重建 / 升级不触发「换机」判定**：否则每次 `docker compose up --force-recreate` 都要重发激活码。
- **宿主重装系统** → 宿主锚点变化 → 判异机 → 后台「废弃 + 重发」。
- **锚点缺失降级**：宿主无可读锚点（精简宿主 / 受限内核）时，以安装脚本生成的签名指纹文件为准，容器只读该文件。

## 7. 一机一码冲突检测判定逻辑（服务 activation_code 1:1 绑定，供 task 46 实现）

同一激活码在新机器上发起激活时，服务端按序判定：

| 步骤 | 条件 | 判定 | 动作 |
|------|------|------|------|
| ① | 上报 `machine_code` 与绑定记录一致 | 同机 | 正常激活 / 恢复凭证，重签租约 |
| ② | 不一致，但 `anchor_hashes` 命中 ≥4/5 | 同机（重装 / 漂移） | 更新绑定 machine_code、作废旧租约、重签新租约，审计留痕 |
| ③ | 命中 ≤3/5 | **异机** | **拒绝：403 `CODE_BOUND_TO_OTHER_DEVICE`** + 审计留痕；客户端仅提示「申请换机」→ 后台废弃 + 重发（task 42） |
| ④ | 激活码状态 ∈ {revoked} | 已废弃 | 拒绝激活（对齐 task 42 状态机） |

- 判定**只在服务端执行**（licensing-server），客户端不预判、不缓存「是否同机」结论。
- 所有拒绝与自动改绑均写审计日志（谁、何时、命中几项、漂移项），供后台人工核实。

## 8. 口径对齐

- task 40：前端不可保密 → 指纹与判定全部在 Rust 侧 + 服务端。
- task 42：换机唯一路径 = 管理后台「废弃 + 重发」；激活必须联网。
- task 44：`device` 表记录部署形态（native / docker）与镜像 digest、首次激活时间。
- task 59：宿主锚点方案、持久卷布局、`host-fingerprint.json` 与本文件完全一致。
