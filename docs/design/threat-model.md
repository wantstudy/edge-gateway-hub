# iot-daq 威胁模型与防御矩阵（对应计划 task 40）

> 配套图：`docs/design/auth-architecture.svg`（四类参与方 × 三个信任区 × A/B/C 三档信任边界）。
> 定位声明：**提高成本 ≠ 绝对防破解**。防御目标是拦掉 90% 非专业破解尝试，并让专业破解者付出 > 数人日仍无法获得云端有效授权；预算分配 控制面 : 客户端 = 7 : 3。
> 与 Must NOT Have 一致：不使用内核驱动 / 硬件加密狗 / 隐写水印；签名针对规范化摘要，不直接签序列化字节。

## 1. 攻击者能力假设

- 可获得现场设备的物理访问与管理员权限（读写文件系统、重装系统、调试进程）。
- 可控制设备侧网络（中间人、阻断、重放）。
- 可获得正版安装包与激活码样本，可搭建虚拟机反复实验。
- **不能**：攻破 Ed25519 签名私钥（KMS / 离线托管，与业务 API 隔离）；攻破厂商云（licensing-server / admin-console）。

## 2. 攻击面与防御矩阵

| # | 攻击手段 | 攻击者前提 | 防御措施 | 残余风险 |
|---|---------|-----------|---------|---------|
| 1 | 伪造机器码（构造假指纹骗取激活） | 可控制本机上报内容 | 多源锚点 N-of-M 匹配（≥5 锚点、允许 1 项漂移）+ HMAC-SHA256（厂商私密盐）截断指纹，无盐不可离线枚举预计算；服务端一机一码绑定 + 冲突检测；容器形态只认宿主锚点（task 41/59） | 攻击者若以虚拟化/定制内核同时伪造多数硬件锚点可伪装"新机"，需逐字段伪造且无盐值，成本高、非零 |
| 2 | 拷贝授权文件到另一台机器 | 拿到正版机上的授权凭证 | Lease Token 绑定机器码指纹，本地每次启动重算指纹比对；SQLCipher 本地库以机器码派生密钥（HKDF，task 34）加密，异机解不开；心跳携带设备身份，云端可发现异常 | 同型号批量克隆机锚点高度重叠时存在小概率误判同机，需以 N-of-M 阈值平衡误杀/漏判 |
| 3 | 篡改本地时钟（回拨延长试用/宽限） | 管理员权限 | 单调时钟 + 记录历史最大时间 + 与服务端时间比对，回拨判异常；试用期以云端首次激活时间为准；异常记审计 | 长期离线 + 回拨组合只能靠本地记录的最大时间兜底，无法完全检测 |
| 4 | 重放旧 Token / AuthBlock（激活响应重放到他机） | 抓获历史激活/校验报文 | 激活与 A 档 /verify 响应带 Nonce，服务端全局 Nonce 缓存防重放 + ±5min 时间窗；Token 绑定机器码与租约 id，跨机验签即拒 | B/C 档本地验签不联网校 Nonce，同机重放"有效期内旧 Token"收益极低（机器码一致），跨机被机器码绑定阻断 |
| 5 | patch 二进制绕过授权判定 | 可逆向与修改可执行文件 | Tier-1：strip / LTO / panic=abort、字符串与常量混淆、段哈希完整性自检、低成本反调试；检测到篡改 → 受限模式（停北向转发 + 审计告警）；云端以心跳缺序号区间告警兜底 | **Tier-2/3 明确不做**：专业破解者可 patch 绕过本地判定（B 档还可抑制回执、断网静默自用）；只能提高成本与可检测性 |
| 6 | 劫持前端 WebView 调用（改 JS / 伪造 IPC） | 前端资源等同公开，可解包读改 | 授权判定一律在 Rust 侧，前端仅展示；前端资源由 Rust 启动时做完整性清单哈希校验；密钥、激活码、签名算法细节一律不放前端 | 篡改后的前端可制造"显示层假象"误导运维（不影响数据面），需配合完整性校验与服务端审计发现 |
| 7 | 中间人改激活 / 心跳响应 | 控制设备侧网络 | 全链 TLS；响应由服务端 Ed25519 签名，本地用内置公钥（kid 公钥集）验签；A 档另加 ±5min 时间窗 + 全局 Nonce | 无法防纯阻断（拒绝服务），但阻断只会触发 7 天宽限 → 降级 → 停北向转发，不能伪造有效授权 |
| 8 | 重装系统重用试用期 | 可格式化重装 | 试用标记四重冗余：文件 + 注册表/配置目录 + SQLCipher 库 + 云端首次激活时间，交叉校验；重装后硬件锚点指纹大概率不变 → 云端首激时间识别为同设备，试用不重置 | 换整机 + 重装可获新试用期（与正常换机同路径，商业上可接受）；全盘换新硬件无法与真新装机区分 |
| 9 | 删除 / 篡改本地授权与试用标记文件 | 文件系统写权限 | 多位置冗余交叉校验，单点删除以其余副本 + 云端首激时间兜底；凭证经 DPAPI（Windows）/ keyring（Linux）加密落盘 | 全盘格式化 + 换机与"全新安装"不可区分 |
| 10 | B 档抑制审计回执 / 完全断网静默自用 | 破解代码可控上报逻辑 | 心跳缺序号区间、回执缺失/回退 → 云端风控告警并降级；回执允许断网延迟补报 | **防御不住**（见 §3 第 1 条）：破解代码可不发回执并断网，厂商只能发现"失联"，无法阻止静默自用 |

## 3. 防御不住什么（明示残余风险，避免客户预期错位）

1. **B 档破解后可完全断网静默自用**：破解者可篡改代码不上报审计回执并不出网。兜底只能靠「心跳缺序号区间即告警降级」——**只能发现，无法阻止**。
2. **Tier-2 / Tier-3 反破解手段明确不做**：Tier-2（控制流平坦化、字符串加密、模块交叉校验、Frida 检测）暂不做；Tier-3（内核驱动、VMProtect/Themida 级商业壳、硬件加密狗）不做（与 Must NOT Have 一致）。
3. **客户端前端资源不可能保密**：Tauri WebView 的 JS/CSS 等同公开源码，可解包读改；因此授权与防篡改判定绝不放 JS 层，机密一律不放前端，前端仅做完整性哈希校验。

## 4. A/B/C 三档小结（详见架构图下部三栏）

| 档位 | 控制通道 | 厂商能验证 | 厂商验证不了 |
|------|---------|-----------|-------------|
| A（数据经厂商云） | /verify 全链校验 | 验签、±5min 时间窗、全局 Nonce、字段白名单、计量 | 客户端二进制是否被 patch 绕过本地判定 |
| B（默认） | 24h 心跳 + POST /audit/receipt（序号区间+条数+摘要，无业务数值） | 转发是否发生、序号连续性（跳空/回退/缺失告警） | 业务数值真伪；回执是否被破解代码抑制 |
| C | 仅租约心跳 | 设备存活与租约有效 | 任何业务侧信息 |
