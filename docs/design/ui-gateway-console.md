# 客户端界面设计（网关侧 web-console）

> 承载端：Windows Tauri WebView（主）+ Linux/容器场景下宿主机浏览器访问 `https://<host>:8080`
> 同一份前端代码，两种承载；**授权判定一律在 Rust 侧**，前端只做展示与可见性控制。
> 配套：`ui-design-system.md`、`prototype/iot-daq-ui-prototype.html`（可直接点击走一遍）

---

## 1. 设计目标

现场工程师在**车间办公室或产线旁**用一台工控机/笔记本完成「接线 → 建点 → 配转发 → 盯运行 → 处置异常」的全流程。因此：

1. **动线优先**：导航按运维动线排序（总览 → 接入 → 点位 → 转发 → 监控 → 告警 → 授权 → 日志 → 设置），不按技术模块排。
2. **一屏看全**：常用信息（在线设备数、转发速率、队列水位、授权剩余）在总览一屏内可见。
3. **异常可处置**：任何异常（离线、跳空、授权降级、队列高位）都能从页面上直接找到「下一步做什么」。
4. **授权可见**：授权/试用状态常驻顶栏，降级必须写明原因与恢复路径。

要点：**校验预览必须给出「行号 + 原因 + 允许值」**；工业点表动辄数百行，不能靠人工比对。导出与导入模板**字段顺序必须一致**（保证「导出 → 改 → 导入」闭环，这是现场最高频操作）。

**公式列同样纳入导入导出**：`point_type`（physical / derived）与 `formula` 为导出列；公式含逗号、引号、括号（如 `if([T]>80,1,0)`）时 CSV 必须正确转义。导入除逐行校验外，必须做**整表级环检测**——跨行成环（`R_A=[R_B]+1`、`R_B=[R_A]+1`）逐行看各自合法，只有整表拓扑才能发现。

### 3.3.1 公式编辑器（计算点 / 派生点）

计算点指「值由其他点位经公式算出」的点位（例：单位能耗 = 注射压力 × 温度系数 / 1000）。它与物理点在同一张点位表里管理，但必须**视觉可区分**，否则现场容易误当作传感器点位排查。

```
公式编辑器（抽屉）· 计算点
点位名称 [单位能耗]      输出类型 [float32 ▾]   单位 [kWh]   死区 [0.01]
表达式（引用点位用 [ ] 包裹）
┌────────────────────────────────────────────────────────────────────────┐
│ ([P_Inj] * [T_Barrel1]) / 1000 * 0.2778                                │
└────────────────────────────────────────────────────────────────────────┘
✓ 语法正确      ✓ 无环      依赖 2 个                  [校验]  [后端试算]

依赖（自动解析）
  [P_Inj]      注射压力     当前 86.4 MPa     Good
  [T_Barrel1]  料筒温度1    当前 213.5 ℃      Good

插入函数（白名单，点击插入）
  abs  ceil  floor  round  clamp  min  max  sqrt  pow  exp  log  log10
  if(cond,a,b)    prev(x)    delta(x)    rate(x)    hold(x,n)    quality(x)

试算结果（后端 dry-run · 权威）
  按当前输入值 → 5.12 kWh      quality = Good

失败策略
  ( • ) 保留上次有效值并标记质量（默认）    (  ) 置空    (  ) 不输出

ⓘ 公式变更只对新增数据生效，历史数据不重算。
                                                [取消]   [保存]
```

环检测失败（保存被拒）

```
✘ 依赖成环，无法保存

  环路径：  E_Unit（单位能耗） → C_Unit（单件成本） → E_Unit

  修复建议：移除环上任意一条引用后重试。

  [定位到 E_Unit]   [定位到 C_Unit]
```

要点：
- **前端只做即时提示**（语法、依赖、环），**权威校验与试算都在网关侧**：保存前必须过 `POST /api/points/formula/validate`，试算必须走 `POST /api/points/formula/dry-run`。禁止以本地求值结果为准（两端实现必然分歧）
- **环检测必须给环路径**，只报「存在循环」等于没报；多级环（A→B→C→A）需完整列出
- 计算点行以**类型 Tag** 与物理点区分；公式变更前须提示「历史数据不重算」
- 不允许「静默批量套用同一公式」——公式必须逐点显式确认

要点：
- 编码是**每路出口独立单选**，默认 protobuf；选 JSON 时**必须内联展示精度与性能提示**（防止客户误以为 JSON 更通用更好）。
- 「编码一致性自检」把 task 62 的跨端哈希口径一致性测试**做成页面可见能力**，客户改编码后可自证。
- 「测试发布」发布一条样例消息并显示原始 payload（截断）+ 编码声明（MQTT 5 `Content-Type`）。

## 4. 关键流程

### 4.1 首次初始化向导（4 步）
`管理员口令（强制修改默认口令）` → `授权（试用 / 输入激活码）` → `接入首个设备（协议向导 + 测试连接）` → `配置首个北向出口（含编码选择 + 测试发布）`。任何一步可跳过，跳过项在总览显示为待办清单。

### 4.2 从零到数据上云（典型 6 步）
新增设备 → 测试连接 → 建点（或导入点表）→ 点位映射与单位/死区 → 配北向出口（选编码）→ 实时监控确认数值 → 在客户 Broker 侧确认收到消息。

**含计算点的扩展路径**：建点完成后 → 「新增计算点」（写公式 + 过校验与试算）→ 实时监控中确认计算点有值且单位正确 → 参与北向转发。注意**公式拿到的是已换算到工程单位的值**（先换算后计算），且计算点与物理点在列表中视觉可区分。

### 4.3 断网续传（现场常态）
断网时总览顶部显示 `--warn` 条：「北向出口 1 不可达，数据已转入磁盘队列（3.2 GB，可续传 ≈4.1 天）。本地采集继续。」恢复后补发，补发期间显示「补发中 128,400 / 1,800,000 条（≈6 分钟）」，完成后记审计。

### 4.4 授权降级（必须可解释）
| 触发 | 页面表现 | 恢复路径 |
|---|---|---|
| 试用到期 | 横幅：`--warn`「试用已到期，已降级为免费基础版；北向转发已停用，本地采集继续」 | 输入激活码 |
| 心跳超期（>7 天） | 横幅：`--danger`「云端心跳超期，北向转发已停用；本地采集继续」+ 网络排查入口 | 恢复网络 / 联系厂商 |
| 激活码被后台废弃 | 横幅：`--danger`「本机授权已被厂商停用（受理编号 RV-2026-0912）。请联系厂商重新发放激活码。」 | 用新码重新激活 |

### 4.5 换机流程（客户侧视角）
本机机器码变化 → 授权页显示「机器码已变化（原 8F3A… → 新 C1D2…），需厂商重新发放激活码」→ 客户点「申请换机」提交 → 厂商后台废弃旧码、重发新码 → 客户输入新码激活。

### 4.6 全局横幅优先级
`激活码被废弃` > `心跳超期` > `试用剩余 ≤2 天` > `队列高位` > `实时通道断开` > `安全模式`。同屏只显示一条，其余折叠。

## 6. 验收要点（写入对应任务）

- [ ] 未初始化时强制进入向导；默认口令未改前禁止进入业务页面
- [ ] 设备新增必须能「测试连接」并按协议动态切换参数表单
- [ ] 点表导入必须支持 CSV/XLSX，校验结果含**行号 + 原因 + 允许值**，支持「仅导入有效行」
- [ ] 导出文件与导入模板字段顺序一致（导出→改→导入闭环可用）
- [ ] 点位表区分物理点与计算点（类型 Tag）；计算点行「地址 / 字节序」为空、公式列显示摘要

- [ ] 保存必须过后端 `validate`（不可绕过）；试算结果来自后端 `dry-run`，API 不可用时显示「试算不可用」而非伪造结果

- [ ] 运行监控中计算点有值且单位正确（验证「先换算后计算」的时序）
- [ ] 北向编码按出口独立可选；选 JSON 时内联显示精度与性能提示；一致性自检可运行
- [ ] 实时监控 200 设备场景下渲染节流生效（CPU 占用有基线记录）
- [ ] 授权页显示机器码与锚点来源；客户端**不存在**废弃/解绑/重置试用入口
- [ ] 三种降级场景各有横幅，且说明原因与恢复路径
- [ ] viewer 登录后写操作按钮全部不可见（`RoleGate`），直接调用写接口返回 403
